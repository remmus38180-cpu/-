## 一、排序的設計：兩個分數，不是一個

您要求「把最可能的擺前面，並告訴人是怎麼擺的」。實作時把分數拆成**兩個**，
而不是合成一個總分：

| 分數 | 回答的問題 |
|---|---|
| **藥品相符度** | 這筆是不是我要找的那個藥？ |
| **原廠可能性** | 這筆是不是原廠藥？ |

分開的理由：您在做的本來就是兩件事。混成一個分數，看到 85 分時無從得知
是因為藥對、還是因為像原廠。分開之後，「藥品相符度 97、原廠可能性 35」
一眼就看得出這筆藥找對了但不像原廠。

**排序方式**：先依藥品相符度由高到低 → 相同時依原廠可能性由高到低 →
再相同時依單位藥價由低到高。

## 二、說明與計分來自同一張表

介面上「排序是怎麼決定的？」面板顯示的規則，與程式實際計分用的是
**同一份資料**（`drugprice/matching/scoring.py` 的 `DRUG_RULES` 與
`ORIGINATOR_RULES`）。改了規則，說明會跟著變；不可能出現算一套、講另一套。

測試 `test_rules_table_matches_the_rules_used` 就是在守這條線。

### 藥品相符度

| 條件 | 分數 |
|---|---:|
| 成分名完全相符 | +50 |
| 成分名相符（去除鹽類或水合物字尾後） | +45 |
| 成分名以片假名轉寫後高度近似（近似度 ≥ 0.90） | +45 |
| 商品名完全相符 | +45 |
| 成分名以片假名轉寫後近似相符（≥ 0.75） | +35 |
| 記錄的商品名包含查詢的商品名 | +35 |
| ATC 代碼完全相符（7 碼） | +30 |
| 成分名部分相符 | +25 |
| 商品名以片假名轉寫後近似相符 | +25 |
| 商品名部分相符 | +15 |
| 含量相符 | +12 |
| ATC 分類相符（前 5 碼） | +10 |
| 劑型相符 | +8 |

### 原廠可能性

| 條件 | 分數 |
|---|---:|
| 該國官方檔案標示為原廠藥 | +60 |
| 該國官方檔案標示為原研藥 | +55 |
| 該國官方檔案標示為生物原廠藥 | +55 |
| 商品名與輸入完全相符 | +25 |
| 記錄的商品名包含查詢的商品名 | +20 |
| 商品名以片假名轉寫後近似相符 | +18 |
| 藥商名與輸入相符 | +15 |
| 商品名部分相符 | +10 |
| 該國官方檔案標示為學名藥 | **−40** |

上限均為 100，原廠可能性下限為 0。

**學名藥是扣分不是排除**，因為官方分類偶有例外，仍列出供人核對。

**商品名同時計入兩個分數**，這是刻意的：商品名相符既是「這是不是我要找的藥」
的證據，也是「這是不是原廠」的證據（學名藥通常不沿用原廠商品名）。
兩邊的規則描述都會顯示出來，不會讓人以為只算了一次。

## 三、每一筆候選都寫出它為什麼排在那裡

實際輸出的樣子：

> **排序依據：** 藥品相符度 97 ＝ 成分名完全相符 +50、記錄的商品名包含查詢的商品名 +35、
> 含量相符 +12；原廠可能性 95 ＝ 該國官方檔案標示為原廠藥 +60、
> 記錄的商品名包含查詢的商品名 +20、藥商名與輸入相符 +15。
> 排序用的單位藥價為 0.9825 EUR／藥局零售價。

三種額外的提醒也會一併顯示：

**同分提醒**——分數完全相同的相鄰候選會標註：

> 此筆與相鄰候選的兩項分數完全相同，先後僅由單位藥價決定，不代表更可能正確。

這點很重要。瑞典的實測就出現這種情形：Eliquis 的原廠（Bristol-Myers Squibb）
與平行輸入商（Abacus Medicine、Orifarm）分數完全相同，排第一的其實是平行輸入商，
只因為單位藥價低了 0.0008。若不講明，人會誤以為第 1 順位比較有依據。

**無官方註記提醒**——該國檔案沒有原廠／學名藥欄位時：

> 此來源的官方檔案沒有原廠／學名藥註記欄位，本欄僅依商品名與藥商名推估，
> 可信度低於有官方註記的國家。清單中若補上藥商名（如 Bristol-Myers Squibb），
> 可把原廠與平行輸入商區分開來。

提醒同時給出可以怎麼補救，不只是說「不準」。實測補上藥商名後，
法國 Eliquis 的原廠可能性由 80 升到 95。

**近似比對提醒**——片假名轉寫的比對會在規則名稱後附上近似度，
例如「成分名以片假名轉寫後高度近似（近似度 1.00）+45」。

## 五、跨語言比對（日本）

日本的藥價檔用片假名寫成分名與商品名（アピキサバン、エリキュース），
英文清單直接比對會得到**零個候選**——這是實測發現的。

作法是把片假名機械轉寫成羅馬字後做近似比對，並針對日文外來語的規律做正規化：

- 日文沒有 L 音，一律寫成ラ行 → r 與 l 視為同音
- ヘボン式的 chi／shi／tsu 對應外來語的 ti／si／tu
- 日文音節化時會插入英文沒有的母音（statin → スタチン → sutatin）
  → 另外比對「只留子音的骨架」，取兩者較高者

以實際藥名測試的分離度：

| | 近似度範圍 |
|---|---|
| 正確配對（12 組） | 0.80 – 1.00 |
| 錯誤配對（5 組） | 0.21 – 0.62 |

門檻取 0.75，兩者不重疊。12 組正確配對中有 9 組的子音骨架完全相同。

**這是近似比對，不是翻譯。** 比對到的一律標示為「片假名轉寫後近似相符」
並附上近似度數值，讓人知道這一筆的依據比完全相符弱。

實測結果：查詢 Eliquis／apixaban，日本第 1 順位為
`エリキュース錠２．５ｍｇ`／先発品／111.6 円，排序依據寫明
「成分名以片假名轉寫後高度近似（近似度 1.00）+45」。

## 六、操作介面

以標準函式庫的 `http.server` 在本機執行，只綁 `127.0.0.1`，不對外開放。
雙擊 `開啟藥價工具.bat` 會自動開啟瀏覽器。**不需要安裝任何東西，
也不需要看到命令列。**

四個分頁：

1. **總覽**——各國資料是否已下載、幾筆、什麼時候下載的。
   下方另列「本工具不涵蓋的國家」，讓同仁知道不是程式漏抓。
2. **藥品清單**——貼上或選檔。純文字每行一個商品名，或有表頭的 CSV
   （欄位名中英文皆可、順序不拘）。只有商品名時會提醒補成分名。
3. **下載藥價**——勾選國家、執行、看即時訊息。
   澳洲因官方速率限制需約 2 分鐘，介面上有說明，避免同仁以為當掉。
4. **複核候選**——排序規則說明面板、候選卡片、匯出 CSV。
   進入這個分頁時若清單與資料都已備妥，會自動開始比對。

介面最上方固定顯示：

> **排序不是決定。** 程式只是把最可能相符的擺前面，所有候選都會列出來。
> 哪一筆才是原廠藥、哪個規格可以拿來比較，仍然由您判斷。

## 七、實作時發現並修掉的四件事

**1. 法國的正確答案原本只排到 C 級。** 因為 `CIS_bdpm.txt` 沒有成分名欄位，
成分比對整個落空，ELIQUIS 只靠「含量相符 +12」得分——與完全無關的
TEMESTA（lorazepam，恰好也是 2.5 mg）同分。
已加抓 `CIS_COMPO_bdpm.txt`（成分組成檔），27,242 筆中有 27,238 筆補上成分名，
ELIQUIS 的藥品相符度由 12 升到 97。

**2. 商品名相符原本沒有計入藥品相符度**，只計入原廠可能性。
但商品名相符本來就是「這是不是我要找的藥」的證據。已補上，
並改用**以詞為單位**的比對，避免 "Eli" 誤中 "Eliquis"。

**3. 澳洲同一個 PBS code 在原始檔有多列**（依處方集、給付類別分列），
價格完全相同，導致同一個候選底下出現 24 行一模一樣的價格。
已改為相同價格只留一行，並標示「原始檔另有 N 列價格相同」。

**4. 日本的含量欄原本存成文字**（如 `2.5mg`）而非數值加單位，
導致含量比對失效。已改用同一套解析。
