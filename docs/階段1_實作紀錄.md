| 國家 | 來源 | 原始資料量 | 轉出筆數 | 包裝數量缺漏 | 原廠註記 |
|---|---|---:|---:|---:|---|
| 日本 | MHLW 2026-08-13 版 | 12,400 品項 | 12,400 | 550（4.4%） | 4,218 原廠／4,447 學名藥 |
| 法國 | ANSM／HAS | 13,621 包裝 | 27,242 | 466（1.7%） | 2,914 原廠（princeps） |

**筆數大於品項數是刻意的**：一個品項在不同價格類別下是不同的數字，

**包裝數量缺漏的部分一律留空**，並在備註保留原文，不做推測。

## 二、實作過程中發現的五件事

### 1. 澳洲原定的下載網址被 robots.txt 禁止，且舊制已停用

報告中記載的網址為 `https://www.pbs.gov.au/downloads/…-PBS-API-CSV-files.zip`。
但 `www.pbs.gov.au/robots.txt` 明確禁止：

```
Disallow: /downloads/
Disallow: /*.zip$
```

且官方 Data Distribution Project 頁面已載明「legacy outputs have been
discontinued」、「The API has replaced all existing formats (XML and text
files) of PBS schedule data distribution」。

**改採官方公開 API**：`https://data-api.health.gov.au/pbs/api/v3/`

| 項目 | 說明 |
|---|---|
| robots.txt | 該主機無 robots.txt，未設限 |
| 帳號 | 不需要。公開 API 的訂閱金鑰隨官方 Postman collection 公開發布 |
| 格式 | JSON 與 CSV，本工具用 CSV（同樣資料 2.5MB vs 11MB） |
| 速率限制 | **每 20 秒 1 次請求，且由全體使用者共用** |
| 官方文件 | 有 Data Dictionary（PDF），欄位語意可查證 |

程式已強制該來源的請求間隔為 21 秒，全量約 3 頁、2 分鐘取完。
**請勿自行調低間隔**，會影響其他使用者並可能被擋。

> **待確認**：操作手冊指定的 `cp2p`（Commonwealth price to pharmacy）欄位
> 在新 API 中沒有同名欄位。新 API 提供 `determined_price`（官方核定價）、
> `claimed_price`（廠商申報價）、`proportional_price`（比例計價）、
> `weighted_avg_disclosed_price`（加權平均揭露價）四種。
> 對應關係需以官方 Data Dictionary 逐欄確認，在此之前程式**四種全部保留**，
> 不做等同對應，由使用者決定引用哪一種。

### 2. 法國三個檔案的編碼不一致

同一個下載端點提供的三個檔案：

| 檔案 | 編碼 |
|---|---|
| CIS_bdpm.txt | cp1252 |
| CIS_CIP_bdpm.txt | **UTF-8** |
| CIS_GENER_bdpm.txt | cp1252 |

寫死 cp1252 會讓**價格檔**裡所有法文重音字變成亂碼（`comprimé` → `comprimÃ©`）。
已改為自動偵測（先試嚴格 UTF-8，失敗才退到 cp1252）。

> 既有的 `merge_cip_files.py` 若是寫死 cp1252，包裝說明欄位應該會有亂碼，
> 建議檢查一下輸出結果。

### 3. 日本的檔案網址已經換過，寫死行不通

報告記載的 `tp20260715-01_*.xlsx` 系列，在本次實作時已被
`tp20260813-01_*.xlsx` 取代。已改為**先抓公告頁、解析出當期連結**，
並自動取日期最大的一批，不寫死檔案網址。

公告頁網址本身含年度（`/topics/{年}/04/tp{年}0401-01.html`），
藥價改定後會換，程式會依序嘗試本年度與前一年度。

### 4. 比利時同一藥品有多列不同生效日的價格

PRICES 工作表中，32,396 組（藥品碼、交付模式）裡有 **742 組存在多列**，
生效日不同。若不加處理會取到任意一列，可能是歷史價格。
已改為取「生效日不晚於本期版本的最新一列」。

另外，比利時的價格**依交付模式而不同**（官方欄位說明文件確認）：

| SPB_DEL_ID | 交付模式 |
|---|---|
| 1 | 公眾（publique） |
| 2 | 門診（ambulatoire） |
| 3 | 住院（hospitalisée） |
| 4 | **出廠（ex-usine）** |
| 5 | 安養機構（maison de repos） |

同一個藥品，出廠價與公眾價格是完全不同的數字。價格類別代碼已一併帶上
交付模式，只有完全相同的代碼才可互相比較。

### 5. 五國中有四國的官方檔案帶有原廠／學名藥註記

這對「原廠判定」這一步幫助很大——不必靠商品名與藥商名硬猜：

| 國家 | 欄位 | 原廠的值 |
|---|---|---|
| 日本 | 先発医薬品 | `先発品` |
| 法國 | CIS_GENER 的 Type de générique | `0` = princeps |
| 比利時 | OGC_LBL_FR | `spécialité de référence`／`spécialité originale` |
| 澳洲 | originator_brand_indicator／innovator_indicator | `Y` |
| 瑞典 | 無此欄位 | — |

**程式仍不自動選定原廠藥**，只把註記轉入「原廠註記」欄作為線索，
由複核的人拍板——這是提案中調整一的作法，不因為有官方註記就改變。
原因是官方註記的定義各國不同（例如比利時就有 16 種值，含生物藥、
平行輸入、孤兒藥等），要不要採信仍是判斷。

## 三、統一欄位

共 31 欄，分六組。完整定義見 `drugprice/core/schema.py`。

| 組別 | 欄位 |
|---|---|
| 來源 | 國家代碼、國家、來源機關、來源軌別 |
| 藥品識別 | 原生碼種類、原生碼、商品名、成分名（原文）、ATC代碼 |
| 規格 | 劑型、含量數值、含量單位、**包裝數量**、包裝單位 |
| 價格 | 當地價格、幣別、**價格類別代碼**、價格類別、單位藥價、**單位藥價算式** |
| 原廠判定線索 | 藥商、原廠註記、首次收載日期 |
| 佐證 | 資料版本日期、下載時間、來源網址、原始檔、原始檔雜湊、原始檔位置 |
| 品質 | 欄位對照可信度、備註 |

「單位藥價算式」欄會寫出例如 `180 ÷ 30 錠`，讓覆核的人看得到怎麼算的。

「原始檔位置」會寫出例如 `CIS_CIP_bdpm.txt 第 1234 列／第 10 欄`，
任何一筆數字都能回溯到原始檔的哪一列哪一欄。

## 五、robots.txt 的處理

專案先前對加拿大薩省已建立「robots.txt 禁止就不自動抓」的原則。
本階段把這個原則**制度化到程式裡**：每個網域抓一次 robots.txt 並快取，
被禁止的網址一律拒絕下載並拋出說明清楚的錯誤，同時遵守 Crawl-delay
（比利時 INAMI 為 5 秒）。

**沒有用 Python 內建的 `urllib.robotparser`**，因為它只做字首比對、
不支援 `*` 與 `$` 萬用字元。用它來判斷澳洲 PBS 的 `Disallow: /*.zip$`
會得到「允許」的錯誤結論。已自行實作萬用字元與最長規則優先的比對，
並以澳洲的真實 robots.txt 內容寫成測試。
