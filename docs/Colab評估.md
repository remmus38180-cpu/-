# 這個專案適合搭配 Colab 嗎

> 2026-09-14　結論先講：**資料下載可以當備援用，佐證截圖不要用。**

---

## 一、先釐清一件事：目前自動化的部分並不需要瀏覽器

Colab 的賣點是「headless 瀏覽器爬取需要 JavaScript 動態渲染的複雜網頁」。
但本專案目前已自動化的六個國家，**沒有一個需要 JS 渲染**：

| 國家 | 取得方式 | 需要瀏覽器嗎 |
|---|---|---|
| 日本 | 抓公告頁 HTML 取連結 → 下載 xlsx | 否 |
| 法國 | 直接下載四個純文字檔 | 否 |
| 比利時 | 直接下載 xlsx | 否 |
| 瑞典 | 直接下載 xlsx | 否 |
| 澳洲 | REST API（JSON／CSV） | 否 |
| 加拿大薩省 | 直接下載固定寬度純文字檔 | 否 |

加拿大薩省的查詢頁確實是 Vue 單頁應用程式，但**它的整批檔是靜態檔案**——
我是從它的 JavaScript 套件裡找出檔案網址，而不是去渲染那個頁面。
瑞士的新版網站也一樣：與其用瀏覽器渲染，不如找出後端端點。

**一般而言，找後端 API 或靜態檔比渲染頁面更好**：更快、更穩、
不會因為網站改版動到畫面就壞掉，也不會被當成爬蟲。

## 二、Colab 幫不上的三件事

**1. 頻寬不是瓶頸。** 全部十國最大的檔案是德國 G-BA 的 26.7 MB，
其餘多在 1 至 13 MB。真正的瓶頸是澳洲官方的速率限制——
**每 20 秒 1 次請求，且由全世界的使用者共用**。
這是伺服器端的限制，換到 Colab 跑一樣要等。

**2. robots.txt 與使用條款不會因為換執行地點而改變。**
從哪裡發出請求，不影響網站允不允許自動化存取。

**3. 獨立 IP 不是優點，在這個用途上是缺點。** 見下一節。

---

## 三、用 Colab 做佐證截圖會有問題

這是我認為最需要提出來的一點。截圖的用途是
「爭議發生時作為市場交易價的佐證資料」，而佐證的價值來自
**能說清楚這張圖是什麼時候、從哪裡、由誰擷取的**。

從 Colab 擷取會讓這件事變弱，不是變強：

| 問題 | 說明 |
|---|---|
| 地區差異 | Colab 的機器多在美國或其他區域。部分國家的藥品網站會依存取地區調整內容或語言，擷取到的畫面可能與在台灣看到的不同 |
| 執行環境不在掌控內 | Colab 執行階段是暫時的，機器隨時回收、檔案消失。要證明「這個環境當時是什麼狀態」幾乎不可能 |
| 中介變多 | 說明擷取過程時，多了一層「Google 的雲端主機」。爭議時這是可被質疑的環節 |
| 憑證鏈 | 本機執行時可以記錄實際採用的憑證驗證模式（本工具已經這樣做）；經過第三方環境後這個紀錄的意義下降 |

還有一個非技術的問題：**把藥品清單送上 Google 的雲端是資料治理決定。**
那份清單等於揭露健保署正在調查哪些藥品的國際價格，具市場敏感性。
這需要主管與資安單位同意，不是技術選擇。

## 四、Colab 真正有用的三個地方

**1. 公司網路擋掉某些網站時的備援。**
如果環境檢測報告顯示某些官方網站在公司網路連不到，
用 Colab 把**資料檔**下載下來、打包帶回本機再處理，是合理的作法。
這只涉及公開的官方檔案，不涉及佐證截圖。

**2. 開發與測試時的重運算。**
德國 BfArM 的 4 MB PDF 解析、英國 dm+d 的大型 XML，
在 Colab 上試跑比在免安裝版 Python 上快很多。
但**產出的程式最後仍要能在同仁的 WinPython 上執行**——
這是本專案的技術原則，不能因為 Colab 方便就改用第三方套件。

**3. 示範與教學。**
讓同仁或主管看流程實際跑起來，不必先處理環境問題。

## 五、真正需要瀏覽器的那一段，剛好是最不該放上雲端的那一段

把這兩件事放在一起看，結論其實很清楚：

- 本專案**需要 JS 渲染的**，是 B 軌的逐筆查詢頁截圖
  （compendium.ch、FASS、dm+d browser、薩省查詢頁都是單頁應用程式）
- 本專案**最需要可追溯性的**，也正是這些截圖

**需要瀏覽器的那一段，剛好是必須留在本機的那一段。**
所以建議：

| 工作 | 建議執行位置 |
|---|---|
| A 軌整批檔下載與轉換 | 本機優先；公司網路擋住時用 Colab 當備援 |
| B 軌查詢頁截圖存證 | **一律本機**，用 Windows 內建的 Edge 無頭截圖 |
| PDF／大型 XML 解析的開發測試 | Colab 可用，成品要能在 WinPython 執行 |

## 六、已交付的 Colab notebook

`colab/十國藥價下載.ipynb`

**只做資料下載，刻意不含截圖功能。** 內容：

1. 從 GitHub 取得本專案程式（或手動上傳）
2. 勾選要下載的國家
3. 執行下載與轉換
4. 把 `raw/`（原始檔與雜湊）與 `output/`（轉換結果）打包成 zip 下載回本機
5. 顯示原始檔雜湊清單，回本機後可用 `RawStore.verify()` 核對檔案未被更動

第 5 點很重要：即使在 Colab 下載，**原始檔的雜湊仍然一路帶回本機**，
佐證鏈不會斷在雲端。

> [!warning] 使用前請確認
> 把藥品清單上傳到 Colab 等於把它交給 Google 的雲端服務處理。
> 使用前請先與主管及資安單位確認是否符合單位規定。
> notebook 第一格就寫了這段提醒。
